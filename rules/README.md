# rules —— 规则说明与前提（第 3 周起填写）

每条规则一个文件，文件名即规则 ID，例如 `R01_group_equal_data_bits.md`。必须写清：

1. **触发条件**：什么结构才适用（位宽、分支数、重复密度、是否可证明互斥）。
2. **语义前提**：依赖哪些前提（例如"上游译码互斥"，前提来源必须可证明，不得假定）。
3. **变换摘要**：具体改了什么（前后结构对照图放在 `reports/`）。
4. **成本估计**：轻量估计式 + 实测值（相同单元数时偏好较小深度/扇出、较短耗时）。
5. **对应测试**：`benchmarks/` 下的用例 ID，以及该规则的专属回归集。
6. **消融开关**：如何单独关闭该规则（规则开关是题目接口要求之一）。
7. **已知无效场景**：哪些电路上无收益或被跳过，**必须保留反例**。

命名与编号要和 `docs/` 中的设计报告、实验报告引用一致，便于答辩时从指标追到代码与证据。

> 首版只做"数据输入结构相同"的判断，**不在每一对数据输入之间调用 SAT 证明函数等价** ——
> 那会把范围扩展成昂贵的通用逻辑综合问题（见方案第 7 节）。

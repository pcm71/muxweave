## 0. 为什么要重规划

两件事同时发生，导致原方案的**技术路线与优先级都不再成立**：

1. **口径错误被纠正**：项目内长期把"面积 10% 为达标线、不到 10% 该项不得分"当赛题规定，
   但**赛题原文没有这条规则**（它源自本项目方案文档的转述，被后续文档反复引用）。
   原文 40 分细则是：**有缩减即得基础分 20 分，达 20% 以上满分，无优化效果才 0 分**。
2. **方案被判定违规**：最新答疑 **C53-1**「请都用 yosys 自带的 abc9 运行，这个需要统一」
   ⇒ 此前靠"把 abc9 换成经典 abc"得到的 20.26% **作废**，现行合规成绩 **5.00%**。

**结论：原方案把几乎全部精力压在"面积"上，而按原文口径，面积只是 40 分里的一部分，
且当前真正的失分大头是"设计文档 + 答辩"（20 分完全空白）与"效率口径未核实"。**

**已排除（均有实验证据，不再重复投入）**：

| 方向 | 结果 |
|---|---|
| abc9 脚本参数（`&if` 的 `-a/-A/-C/-F/-m`、`-R` 延迟松弛、`&fraig`） | 上限 **5.00%** |
| `-D` 延迟目标（100 → 1000000 ps） | 无变化（5.00%） |
| 映射后 LUT 去重（`opt_merge`/`opt -full`） | 0% |
| 对 `$lut` 层重跑 abc9 | 0%（幂等） |
| `&if` 之后追加 GIA 命令（`&dc2`/`&resub`/`&nf`） | 全部失败（破坏 abc9 写回） |
| `&nf` 当映射器 | 全部失败 |
| 结构变换（跨位分组、共享选择子表达式） | 在自制同类用例上 **0%** |
| 自带 pass（`muxpack`/`share`/`opt_reduce`/`opt_muxtree`/`wreduce`…） | 0% 或劣化 |

**尚待验证（按预期收益排序，每个方向限时）**：

1. **在官方 4 个用例上直接做结构重构** —— 此前只在自制同类用例上验证过（0 收益），
   未在官方用例上直接试。**注意**：官方 4 个用例经检查无 don't-care（case 分支全覆盖），
   故预期收益低。
2. **修复/替代 abc9 中 100% 失败的 `&mfs`** —— 经典路径里 `mfs2`（don't-care 重综合）是面积主力，
   而 abc9 的 `&mfs` 在本版本每次报错（"no GIA of boxes"）。若能修复，可能是唯一有量级的杠杆。
3. **自定义 LUT 库**（`abc9 -lut <file>` / `-box <file>`）—— 影响 ABC 的成本模型；
   本项目已有 `lutdefs.txt` 线索（`runs/abc9_script_probe.txt`）。
4. **`&if` 的 LUT 结构参数 `-S` / `-J`** —— 先弄清语法（此前 `&if -h` 因网络含 box 而报错）。

**判定规则**：每个方向**限时验证**；若无收益立即停止。**不为面积牺牲 P0 项。**

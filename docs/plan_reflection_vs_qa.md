## 二、方案中被 Q&A **证实**的部分（方向正确，继续）

## 三、方案**必须修改**的 3 处

### 改动 1（硬要求）：pass 的集成点必须写进 `synth_intel.cc`

- 方案原设计：把 `pmux_opt` 当作**外部脚本流程中的一个步骤**（`proc → pmux_opt → opt_clean → synth_intel`）。
- Q&A 09.23 明确："**优化版应在 synth_intel.cc 中加入你的优化 pass 调用**"。
- **影响**：我们当前 `configs/pipelines.json` 里的 `O_INSERT_A/B` 属于**实验脚手架**，
  不是最终交付形态。最终必须修改 `synth_intel.cc`（在合适位置插入 pass 调用），
  并使用 **`-run` 分段标签**验证插入不影响其它阶段。
- **行动**：把插入点实验结果落到 `synth_intel.cc` 的实际改动上（我们已有源码改动经验与 patch 机制）。

### 改动 2（关键）：效率约束比方案理解得**严格得多** —— 候选池穷举不可行

- 方案第 8 节设想"生成多个候选 → 逐个映射 → 保留最优"。我们已按此实现并实测有效（7.28%）。
- **但 Q&A 09.23 明确：效率开销是"每个用例都需要满足"的 5% 门槛，且 CPU 时间包含 ABC。**
  跑 N 个候选映射 = ABC 时间变成 N 倍 ⇒ **必然远超 5%，效率项直接丢分**。
- **必须改成**：**基于特征的一次性策略选择**（分析开销极低，≈0%），而不是穷举试跑。
  即：自研 pass 分析网表的 PMUX/结构特征 → **直接选定**映射策略 → 只跑一次映射。
  这既是满足 5% 约束的唯一办法，**也更像一个真正的算法贡献**（特征驱动的决策，而非暴力搜索）。
- **行动**：把"候选包络"降级为**离线研究工具**（用于找规律），
  线上形态改成"特征 → 策略"的判定规则；用离线包络数据反过来拟合/验证该规则。

### 改动 3：主算法（跨位分组 + 共享选择子表达式）**已被实测否定**，第 7 节需重写

- 方案第 7 节把"跨位分组 + 共享选择子表达式"作为主算法。
- 我们做了三件套验证（手工改写 + EQY 等价 + 后端对比）：
  | 实验 | 结果 |
  |---|---|
  | u02/m03/K=8 三组手工跨位分组改写 | **0 增益**（连 K=8 重度重复也持平） |
  | 显式一热译码、删不可达默认路径 | 0 增益 |
  | 全部相关自带 pass（muxpack/share/opt_reduce -fine/opt_muxtree/wreduce） | 0 或劣化 |
  | 换调优后端 `if -a` 后重测结构改写 | **仍为 0** |
- **原因（源码级）**：`synth_intel` 内部 `opt -fast -mux_undef -undriven -fine -full` + `abc9` 的
  结构哈希，已经在 AIG 层面吃掉了"多分支共用数据源"这类机会 —— 在 RTLIL 层显式分组是多余的。
- **重写方向**：把"结构变换"换成 **"PMUX 感知的分析 + 映射策略选择"**（见改动 2），
  并以 **ABC 脚本**为主要抓手（这有实测支撑，且被主办方明确允许并要求提交）。

## 四、方案可以**砍掉**的 2 处（省工作量）

1. **Tcl 接口**：Q&A 09.23 明确"**不需要 tcl 接口**"——"yosys 的每个 pass 都类似 tcl 一样
   在脚本中可以写成一行单独调用"。方案中若有 Tcl 封装/命令注册的额外工作，可以删掉。
2. **为隐藏测试集准备的泛化设计**：Q&A 09.23 明确"**只以该 4 个 case 为准，不加更复杂的混合 case**"，
   且"case 都规模不大"。方案中为"千节点规模压力""隐藏测试集"做的防御性设计可以降级为**回归用例**，
   不必作为主要优化目标。

> 注：我们已建成的 40+ 用例（`benchmarks/unit|mixed|exp|large`）**不浪费** ——
> 它们是防止过拟合、验证零劣化、证明效率门槛的**回归集**，答辩时也是有力证据。
> 但**优化目标要收敛到官方那 4 个 case**。

## 五、被暴露的**最大风险**：我们手里没有官方的 4 个 case

Q&A 09.04 说测试用例"已上传到 QQ 群 4 个 case"，09.23 确认"只以该 4 个 case 为准"。

**现状：我们目前用的是自己构造的用例，从未见过官方那 4 个 case。**

后果：
- 一切面积优化都是**盲调**：`if -a` 在 l03 上省 13%，在 l04 上却劣化 44%
  —— 官方 4 个 case 的"性格"完全决定成败，猜不得。
- 效率 5% 门槛也只能等拿到 case 才能核算。
- 我们的候选包络结论（哪类电路吃哪套策略）**必须在官方 case 上重新验证**。

**行动项（最高优先级）**：从 QQ 群下载那 4 个 case，纳入 `benchmarks/official/`，
并对它们重跑全部对照（B0 / 经典 abc / `if -a` / 其它候选 / 效率核算）。
